## 2. In-game play-through (dev server and a real client)

`tools/qa/fellowship_checks.py` drives a development server over RCON and a real client under Xvfb (key presses and
clicks through xdotool) on a fresh flat world. The same 16 checks run on every version and loader:

1. to 5. recruit one ally of each class; 6. five allies in the world; 7. the warband summary; 8. allies follow into
formation; 9. aggro labels ride engaged enemies; 10. the warband kills a zombie pack; 11. allies follow again after
the fight; 12. an ally at zero health is downed instead of killed; 13. crouching beside it revives it; 14. the
command wheel (hold G, point, release) gives an order; 15. the Warbanner is planted with a right-click; 16. the
allies guard the banner.

jar (and Fabric API where needed), and boots a production client with a test observer that never ships in a release.

## Fixed during verification

- **Aggro labels** were invisible beyond about 3 blocks: the label entity is 0.05 blocks across and vanilla skips
  drawing entities farther than 64 times their size. They now draw to 48 blocks (all versions).
- **Allies stopped following after a fight, and a Mender's revive ran slow:** the formation, revive and fall-back
  goals ran on alternate ticks. They now tick every tick (all versions); check 11 covers it.
- **Test harness:** the boot observer picked whichever loaded copy of the Minecraft class came last (Forge 1.21.1
  loads it twice) and read a private registry field; the smoke test now sets software-GL defaults on Linux (26.3
  NeoForge's early window needs them); the QA world is cleared of slimes until none are left, with the 26.x game
  rule names.
